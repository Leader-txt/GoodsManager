# 模块五：库存管理

---

## 1. 模块概述

库存管理模块负责**货架管理**和**商品出入库操作**。仓库操作员通过该模块维护库存数据，系统在订单支付成功时自动触发扣减库存（或由操作员手动确认出库），在总部供货或退货时执行入库操作。每次出入库均记录详细日志。

### 1.1 涉及角色

| 角色 | 可用功能 |
|------|----------|
| 仓库操作员 | 货架管理、出入库操作、库存查询 |
| 管理员 | 查看出入库日志 |
| 系统 | 支付成功后自动触发通知（可选：自动扣减库存） |

### 1.2 涉及数据表

| 表名 | 说明 |
|------|------|
| `shelf` | 货架表 |
| `inventory` | 库存表（商品 + 货架 + 数量） |
| `inventory_log` | 出入库日志表 |
| `product` | 商品表（关联查询） |

## 2. 货架管理

### 2.1 货架编码规则

```
货架编号格式：A-B-C

  A  ——  货架编号（数字，如 1, 2, 3...）
  B  ——  层数（数字，从 1 开始）
  C  ——  该层上的位置（数字，从 1 开始）

示例：
  3-2-5  →  3号货架 第2层 第5号位
  1-1-1  →  1号货架 第1层 第1号位
```

## 4. 库存自动扣减策略

> **设计决策**：库存变更时机有二选一方案：

| 方案 | 扣减时机 | 优点 | 缺点 |
|------|----------|------|------|
| **A（推荐）** | 支付成功后自动扣减 | 避免超卖，库存实时准确 | 需事务保证 |
| B | 仓库操作员手动出库 | 灵活，可合并拣货 | 存在延时，可能超卖 |

> 本次采用**方案 A**：支付成功时系统自动扣减库存；仓库操作员出库操作为确认动作（更新订单状态为 `shipped`）。

## 5. 后端 API 设计

> 所有接口均需 JWT 认证（仓库操作员角色，管理员可查看日志）。

### 5.1 货架接口

#### GET `/api/shelves` — 货架列表

支持分页。

#### POST `/api/shelves` — 添加货架

```json
{
  "shelfCode": "4-1-1",
  "description": "台式机区"
}
```

校验：`shelfCode` 格式 `/^\d{1,2}-\d{1,2}-\d{1,2}$/`，且全局唯一。

#### PUT `/api/shelves/:id` — 编辑货架

#### DELETE `/api/shelves/:id` — 删除货架

校验：该货架在 `inventory` 中无关联记录才可删除。

### 5.3 出入库接口

#### POST `/api/inventory/stock-in` — 入库

```json
{
  "productId": 1,
  "shelfId": 1,
  "quantity": 20,
  "remark": "总部供货"
}
```

**处理逻辑：**

1. 校验 productId 和 shelfId 存在
2. 校验 quantity > 0
3. 开启事务：
   - UPSERT `inventory`（product_id + shelf_id 唯一约束），quantity += 入库量
   - INSERT `inventory_log`（type = 'in'）
   - INSERT `system_log`
4. 提交事务

#### POST `/api/inventory/stock-out` — 出库

```json
{
  "productId": 1,
  "quantity": 1,
  "orderId": 15,
  "remark": ""
}
```

**处理逻辑：**

1. 校验当前库存 >= 出库量
2. 开启事务：
   - UPDATE `inventory.quantity` -= 出库量
   - INSERT `inventory_log`（type = 'out'）
   - 若关联 orderId：UPDATE `order.status` = 'shipped'
   - INSERT `system_log`
3. 提交事务

#### POST `/api/inventory/stock-out-batch` — 批量出库（按订单）

```json
{
  "orderId": 15
}
```

自动按订单中 `order_item` 逐项出库。

## 6. 业务规则

| 编号 | 规则 |
|:----:|------|
| BR-I01 | 货架编号格式为 `A-B-C`（三段数字），全局唯一 |
| BR-I02 | 删除货架前校验：若该货架在 `inventory` 表中有记录且 quantity > 0，禁止删除 |
| BR-I03 | 出库数量不得超过当前库存 |
| BR-I04 | 支付成功后自动扣减库存（而非手动出库时扣减），库存扣减与支付确认在同一事务中 |
| BR-I05 | 订单超时取消时，已扣减的库存自动回退 |
| BR-I06 | 每次出入库操作必须写入 `inventory_log` 和 `system_log` |
| BR-I07 | 入库操作不限制数量上限 |

## 7. 数据库操作摘要

| 操作 | SQL 类型 | 说明 |
|------|:--------:|------|
| 货架列表 | SELECT | shelf 表分页查询 |
| 添加货架 | INSERT | shelf 表 |
| 删除货架 | DELETE | 需先 SELECT inventory WHERE shelf_id 校验 |
| 库存列表 | SELECT + JOIN | inventory JOIN product JOIN shelf |
| 入库 | UPSERT + INSERT × 2 | 事务：inventory ON DUPLICATE KEY UPDATE + log |
| 出库 | UPDATE + INSERT × 2 | 事务：inventory -= qty + log + order.status |
| 库存扣减（支付） | UPDATE + INSERT × 2 | 同出库，由 order service 调用 |
| 库存回退（取消） | UPDATE + INSERT × 2 | inventory += qty，type = 'in'，remark = '订单取消回退' |
