# 模块四：订单管理

---

## 1. 模块概述

订单模块是系统的核心交易模块，覆盖**线上购买**和**线下购买**两条完整流程，包括订单生成、支付确认、物流跟踪、订单签收、超时取消等全生命周期管理。

### 1.1 涉及角色

| 角色 | 可用功能 |
|------|----------|
| 顾客 | 创建订单、查看自己的订单、确认签收 |
| 销售人员 | 为线下顾客创建订单、确认现场结付、录入物流信息 |
| 管理员 | 查看所有订单 |
| 系统（定时任务） | 超时未支付订单自动取消 |

### 1.2 涉及数据表

| 表名 | 说明 |
|------|------|
| `order` | 订单主表 |
| `order_item` | 订单明细表 |
| `cart` | 购物车表（结算后清除） |
| `inventory` | 库存表（支付后扣减，取消后退回） |
| `system_log` | 系统日志表 |

```

                    │ 待支付    │ ← 订单创建初始状态
                    │ pending  │

              ▼          │          ▼

        │  paid    │    │    │ cancelled│

             │          │
             │ 仓库出库  │
             ▼          │
        ┌──────────┐    │
        │ 已出库    │    │
        │ shipped  │    │
        └────┬─────┘    │
             │          │
             │ 物流揽收  │
             ▼          │
        ┌──────────┐    │
        │ 配送中    │    │
        │delivering│    │
        └────┬─────┘    │
             │          │
             │ 顾客签收  │
             ▼          │
        ┌──────────┐    │

        │ signed   │    │

            货到付款：pending → paid（跳过在线支付等待）
```

## 4. 后端 API 设计

### 4.1 顾客接口（需 JWT + customer 角色）

#### POST `/api/orders` — 提交订单

**请求体：**

```json
{
  "cartItemIds": [1, 2],
  "address": "上海市浦东新区XXX路XXX号",
  "payMethod": "online",
  "deliveryType": "delivery"
}
```

**处理流程：**

```
1. 校验 cartItemIds 非空，且属于当前用户
2. 查出购物车项对应的商品和当前库存
3. 逐项校验 quantity <= stockQuantity，任一不足则返回错误
4. 生成订单编号 (规则：YYYYMMDD + 6位自增序号)
5. 开启事务：
   a. INSERT order（status = 'pending'）
   b. 批量 INSERT order_item（快照价格）
   c. DELETE 购物车中已下单的项
6. 写 system_log（action: 'order_create'）
7. 提交事务，返回订单详情
```

#### GET `/api/orders` — 我的订单列表

| 参数 | 类型 | 必填 | 说明 |
|------|:----:|:----:|------|
| page | int | | 页码，默认 1 |
| pageSize | int | | 每页条数，默认 10 |
| status | string | | 筛选状态 |

#### GET `/api/orders/:id` — 订单详情

返回订单完整信息，含状态时间线、商品明细、物流信息。

#### PUT `/api/orders/:id/cancel` — 取消订单

**条件：** 仅 `pending` 状态可取消。取消后回退库存，写日志。

#### PUT `/api/orders/:id/sign` — 确认签收

**条件：** 仅 `delivering` 状态可签收。签收后状态变为 `signed`，写日志。

#### PUT `/api/orders/:id/pay` — 在线支付确认

**请求体：**

```json
{ "payMethod": "online" }
```

> 注：真实支付对接第三方（如支付宝沙箱环境）。课程设计阶段可使用"模拟支付"——调用此接口直接标记已支付。

### 4.2 销售人员接口（需 JWT + sales 角色）

#### POST `/api/orders/offline` — 创建线下订单

**请求体：**

```json
{
  "customerId": 5,
  "items": [
    { "productId": 1, "quantity": 1 },
    { "productId": 3, "quantity": 2 }
  ],
  "deliveryType": "delivery",
  "address": "上海市浦东新区XXX路XXX号",
  "expressCompany": "顺丰速运",
  "expressNo": "SF1234567890"
}
```

**处理逻辑：**

1. 校验 customerId 有效
2. 逐项校验库存
3. `payMethod` 固定为 `offline`
4. `status` 直接设为 `paid`（现场结付）
5. 若 `deliveryType = 'self_pickup'`：状态直接设为 `signed`
6. 若 `deliveryType = 'delivery'`：必填 address、expressCompany、expressNo
7. 写 system_log
8. 扣减库存

## 5. 定时任务

### 5.1 订单超时自动取消

```
任务名称：auto-cancel-orders
执行频率：每 5 分钟
处理逻辑：
  SELECT * FROM `order`
  WHERE status = 'pending'
    AND pay_method = 'online'
    AND created_at < NOW() - INTERVAL 24 HOUR

  对每条结果：
    UPDATE status = 'cancelled', cancelled_at = NOW()
    回退 inventory.quantity（按 order_item 逐项加回）
    INSERT system_log (action: 'order_cancel', detail: '超时自动取消')
```

> 使用 `node-cron` 实现：

```js
const cron = require('node-cron');
cron.schedule('*/5 * * * *', async () => {
  await orderService.cancelExpiredOrders();
});
```

## 6. 业务规则

| 编号 | 规则 |
|:----:|------|
| BR-O01 | 下单时再次校验库存，库存不足阻止提交（防止购物车到下单期间库存变化） |
| BR-O02 | 订单取消仅限 `pending` 状态，取消后库存自动回退 |
| BR-O03 | 在线支付订单 24 小时内未支付自动取消 |
| BR-O04 | 货到付款和现场结付订单创建后直接标记 `paid`，不进入超时取消范围 |
| BR-O05 | 线下订单自提时，`deliveryType = 'self_pickup'`，状态直接变为 `signed` |
| BR-O06 | `order_item.price` 存储下单时价格快照，后续商品调价不影响已有订单 |
| BR-O07 | 订单号全局唯一，规则：YYYYMMDD + 6 位自增（每日重置），如 `20240601000001` |
| BR-O08 | 每次状态变更均写入 `system_log`，记录操作人、时间、旧状态、新状态 |

## 7. 数据库操作摘要

| 操作 | SQL 类型 | 说明 |
|------|:--------:|------|
| 提交订单 | INSERT × 3 + DELETE | 事务：order + order_item + 删购物车 + 写日志 |
| 订单列表 | SELECT + JOIN | order JOIN order_item JOIN product |
| 订单详情 | SELECT × N | order + order_item + system_log 时间线 |
| 取消订单 | UPDATE × 2 + INSERT | 事务：更新 order.status + 回退库存 + 写日志 |
| 确认签收 | UPDATE | order.status = 'signed' |
| 超时取消 | UPDATE × N | 批量处理，每条回退库存 |
| 线下订单 | INSERT × 3 | 同提交订单，但跳过购物车清理 |
